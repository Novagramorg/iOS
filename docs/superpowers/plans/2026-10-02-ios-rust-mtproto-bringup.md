# Rust MTProto Engine on iOS — Part 1 (Bring-up) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Link the Rust MTProto engine into every iOS build and make it selectable by a next-launch Debug Settings switch, with a logout probe for main-session 401s and foreground liveness, while MtProtoKit stays the default.

**Architecture:** Bazel builds the engine's three crates with `rules_rust` (pinned flags, no LTO, hardware crypto re-applied by hand) behind an `objc_library` C module named `MTProtoEngineFFI`, and the existing Swift wrapper as `swift_library` targets. `AppDelegate` passes `RustNetworkEngineFactory()`; TelegramCore's existing `resolveNetworkEngine` does the rest. Two behaviour changes ride along: the wrapper probes `MTContext.checkIfLoggedOut` instead of logging out on a main-session 401, and a new `NetworkEngineSession.setOnline` seam method carries `Account.shouldKeepOnlinePresence` to the engine.

**Tech Stack:** Bazel 9.2.0 + rules_rust 0.74 (Rust 1.98.1, crate_universe), rules_swift/rules_apple, Swift 6.4, Objective-C (MtProtoKit), SwiftSignalKit.

**Spec:** `docs/superpowers/specs/2026-10-02-ios-rust-mtproto-bringup-design.md` (read it first; this plan argues from it).

## Global Constraints

- MtProtoKit stays the iOS default: `NetworkEngineSettings.defaultSettings` is unchanged (`.rust` on macOS, `.mtProtoKit` elsewhere).
- The engine is linked into every build (App Store included); only the main app passes a factory. Extensions keep `networkEngineFactory: nil`.
- Engine Rust targets: `rustc_flags = ["-Copt-level=3", "-Ccodegen-units=1", "-Cpanic=abort"]`, and **never `-Clto`**.
- Crate versions are pinned with `=` to `third-party/mtproto-engine/Cargo.lock`.
- Swift targets use `copts = ["-warnings-as-errors"]`.
- Work on branch `feature/ios-rust-mtproto-bringup` in the **main checkout** (a fresh worktree has empty submodules and no `build-input/`, so no Bazel command loads there).
- Commit after every task; **never `git push`**. Never `git checkout`/`restore`/`reset` over uncommitted work.
- Never install to a simulator: build, then stop; the user installs and drives the app.
- The full app build is driven by the controller session, never a subagent, and runs as the **sole command** of a background Bash call so the task's exit code is the build's own. Do not append `; echo EXIT=$?`.
- The Bash tool runs zsh: unquoted variables do not word-split.
- Full debug build command (referred to below as **FULL_BUILD**):
  ```sh
  source ~/.zshrc 2>/dev/null; python3 build-system/Make/Make.py --overrideXcodeVersion --cacheDir ~/telegram-bazel-cache build --configurationPath build-system/appstore-configuration.json --gitCodesigningRepository git@gitlab.com:peter-iakovlev/fastlanematch.git --gitCodesigningType development --gitCodesigningUseCurrent --buildNumber=1 --configuration=debug_sim_arm64
  ```
  **RELEASE_BUILD** is the same command with `--configuration=release_arm64`. Add `--continueOnError` after `build` when fixing many errors at once.
- Direct Bazel (host targets only): `./build-input/bazel-9.2.0-darwin-arm64 …` from the repo root.

## Review Focus

1. **A remote "Terminate session" must still log the account out on Rust.** The new probe must not block a legitimate logout. Pinned in Task 5, Step 7 (manual).
2. **`Engine:` must show the engine actually running, not the switch.** With a WEB proxy active and the switch on, it must read `mtProtoKit`. Pinned in Task 4, Step 6 (manual).
3. **Extensions stay on MtProtoKit with the switch on.** The NotificationService log must show `engine mtProtoKit (no factory, preferred rust)`. Pinned in Task 3, Step 11 (manual).
4. **A `debug_*` build must still compile the engine at opt-level 3.** rules_rust follows the compilation mode, and a user flag only wins if it comes last. Pinned in Task 1, Step 8 (aquery).
5. **Foreground/background and account switching must flip `online`.** Wrapper log lines `online`/`offline` on the main session. Pinned in Task 6, Step 9 (manual).

- [ ] **Step 1: Write the link verification script**

Create `third-party/mtproto-engine/scripts/verify-ios-link.sh` and `chmod +x` it:

```sh
#!/bin/sh
# Checks a linked, unstripped Mach-O (e.g. TelegramUIFramework of a debug_sim_arm64 build) for the
# three properties the Bazel build of the Rust MTProto engine must keep. None of them is a build
# error when lost: the crates silently fall back to software crypto (~15x slower), or std is
# duplicated.
#   1. one copy of the Rust standard library (core, alloc, std), shared by every Rust library;
#   2. the ARMv8 AES backend of the `aes` crate (`--cfg aes_armv8`);
#   3. the aarch64 SHA-256 backend of the `sha2` crate (feature `asm`).
set -eu
BIN="${1:?usage: verify-ios-link.sh <Mach-O binary>}"
SYMS="$(mktemp)"
trap 'rm -f "$SYMS"' EXIT
nm "$BIN" | awk '{print $NF}' | grep '^__R' > "$SYMS" || true
if [ ! -s "$SYMS" ]; then
    echo "FAIL: no Rust symbols in $BIN (stripped binary?)"
    exit 1
fi
status=0
for crate in 4core 5alloc 3std; do
    copies=$(grep -oE "Cs[0-9A-Za-z]{1,13}_${crate}[0-9]" "$SYMS" | sed -E 's/[0-9]$//' | sort -u | wc -l | tr -d ' ')
    if [ "$copies" = "1" ]; then
        echo "ok: one ${crate#?}"
    else
        echo "FAIL: $copies copies of ${crate#?}"
        status=1
    fi
done
if grep -q '3aes5armv8' "$SYMS"; then
    echo "ok: aes armv8 backend linked"
else
    echo "FAIL: no aes::armv8 symbols (is --cfg aes_armv8 applied to the aes crate?)"
    status=1
fi
if grep -q '4sha26sha2567aarch64' "$SYMS"; then
    echo "ok: sha2 aarch64 backend linked"
else
    echo "FAIL: no sha2::sha256::aarch64 symbols (is the sha2 asm feature enabled?)"
    status=1
fi
exit $status
```
